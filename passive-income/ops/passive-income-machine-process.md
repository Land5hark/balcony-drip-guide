# Passive Income Machine Process

Purpose: turn the original passive-income plan into a repeatable operating system with Spike as orchestrator and Hermes-style workers as execution lanes.

## Phase 1 — Strategy and guardrails
1. Confirm constraints:
   - free tools first
   - no broad saturated niches
   - one primary site at a time
   - minimal human involvement except identity/payments/legal/risky approvals
2. Confirm operating split:
   - Spike/OpenClaw = orchestration, memory, reporting, approvals routing, system design
   - Hermes-style workers = repeatable execution lanes
3. Confirm success criteria:
   - one site proves useful publication + measurement + monetization path before scaling

## Phase 2 — Niche sourcing
4. Generate candidate niches.
5. Filter for hyper-specific long-tail opportunities.
6. Reject niches with obvious giant-incumbent dominance, weak depth, or fake expertise risk.
7. Keep a shortlist of one primary candidate plus backups.

## Phase 3 — Niche validation
8. Validate keyword/topic depth.
9. Validate evergreen demand or recurring search demand.
10. Validate content depth for 30+ useful articles.
11. Validate audience/problem clarity and buyer intent.
12. Validate that the niche can be written credibly.

## Phase 4 — Affiliate/monetization validation
13. Identify 3-5 likely merchants/programs for the niche.
14. Verify the affiliate path actually exists.
15. Score each merchant with the affiliate scorecard:
   - commission %
   - cookie window
   - average order value
   - conversion potential
   - approval difficulty
   - payout threshold
   - reversal risk
   - brand fit / trust
16. Rank primary / secondary / fallback paths.
17. Reject niches with no primary merchant scoring 70+ and no acceptable backup path.

## Phase 5 — Pilot factory setup
18. Create the niche workspace.
19. Create the operating files:
   - topics
   - products
   - affiliate programs
   - link registry
   - rules
   - templates
   - reports
20. Create the vault/project control surface.
21. Choose the lean publishing stack.
22. Set up hosting, repo, and analytics.

## Phase 6 — Editorial system build
23. Build first 10-20 topic/article candidates.
24. Cluster by intent:
   - troubleshooting
   - maintenance
   - comparisons
   - buying guides
   - accessories/resources
25. Decide publication order.
26. Define internal linking rules.
27. Define affiliate-link governance rules.

## Phase 7 — Production
28. Research each article.
29. Draft each article.
30. Review for usefulness, specificity, credibility, and search intent fit.
31. Insert governed monetization paths where appropriate.
32. Publish to the live site.
33. Log what was published and why.

## Phase 8 — Distribution
34. Support with value-first promotion where appropriate:
   - selective social posts
   - Pinterest if visual fit exists
   - selective community participation only when genuinely useful
35. Avoid spam and fake engagement theater.

## Phase 9 — Measurement
36. Confirm indexing and crawlability.
37. Review analytics/search signals.
38. Track:
   - published useful articles
   - indexed pages
   - impressions
   - clicks
   - affiliate placements completed
   - early conversions
   - time/token cost per workflow
39. Record lessons and friction.

## Phase 10 — Iteration
40. Refresh weak pages.
41. Improve internal links.
42. Expand strong topic clusters.
43. Swap weak merchant paths if economics or trust are bad.
44. Tighten templates and execution SOPs.

## Phase 11 — Scale gate
45. Evaluate whether site one has earned expansion.
46. Only scale if the system proves:
   - repeatable publishing
   - measurable traffic signal
   - believable monetization path
   - manageable human overhead
47. Then and only then expand to site two.

## Standing subagent lanes
- Niche scout lane: generate and shortlist candidate niches.
- Affiliate validator lane: score merchant stacks and reject weak economics.
- Content planner lane: build backlog and intent clusters.
- Drafting lane: produce structured content drafts.
- Publishing prep lane: final formatting, links, and static-site readiness.
- Reporting lane: summarize traffic, monetization, and workflow friction.

## Critical path
The true dependency chain is:
1. niche quality
2. merchant quality
3. publishing system quality
4. measurement quality
5. iteration discipline

If any of those are weak, the machine becomes content cosplay instead of a business.

## Pre-mortem
1. Bad niches pass because they sound interesting.
   - Mitigation: hard-gate every niche with keyword + affiliate validation.
2. Weak affiliate economics get rationalized.
   - Mitigation: enforce the scorecard and reject thin monetization stacks.
3. Too much manual work remains with Sharky.
   - Mitigation: convert recurring tasks into explicit execution lanes.
4. Content gets published without measurement.
   - Mitigation: analytics/indexing checks are required before calling a pilot live.
5. We scale before site one proves anything.
   - Mitigation: require a formal scale gate before adding niche/site two.
